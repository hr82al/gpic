# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

`gpic` — генератор обоев для рабочего стола. Картинка генерируется **локально**
через FLUX.1-schnell на движке `stable-diffusion.cpp` (родственник `llama.cpp`,
та же библиотека `ggml`). Никаких удалённых API, ключей и лимитов.

Репозиторий намеренно состоит из четырёх текстовых файлов. Всё тяжёлое —
движок в `build/` и веса в `models/` — создаётся скриптом и лежит в `.gitignore`.

| Файл | Роль |
|---|---|
| `gpic.py` | вся логика: аргументы, промпт, вызов движков, подрезка, вывод |
| `setup.sh` | развёртывание с нуля: пакеты, сборка, веса, лаунчер |
| `README.md` | инструкция для пользователя |
| `.gitignore` | не пускает гигабайты и секреты в репозиторий |

## Команды

```sh
./setup.sh                    # развернуть всё с нуля (идемпотентно)
python3 gpic.py -r 512x512    # быстрый прогон без установки лаунчера
gpic                          # после установки, из любого каталога
rm -rf build models ~/.local/bin/gpic   # полный откат
```

Тестов нет: логика тонкая, а единственная содержательная операция —
запуск внешнего движка.

## Что важно знать, прежде чем править

- **`gpic.py` — только стандартная библиотека.** Никакого `pip install`:
  утилита должна работать сразу после `git clone`. Не добавляй `Pillow`
  и подобное — нужный размер выдаёт сам движок, обрабатывать картинку
  в Python не требуется.
- **FLUX — четыре файла, а не один.** Диффузионная модель, текстовый энкодер
  T5, CLIP-L и VAE. Без любого из них движок не запустится.
- **Три флага движка — не оптимизация, а условие работоспособности.**
  Все измерены, все прокомментированы в `build_command()`. Не убирай их,
  «упрощая» вызов:
  - `--diffusion-fa` — без него 337 с на шаг вместо 88 и пик 26.4 ГБ;
  - `--vae-tiling` — без него драйвер теряет устройство на декодировании
    и результат гибнет ПОСЛЕ всех отработанных шагов;
  - `--params-backend te=disk` — без него 3.4 ГБ энкодеров висят до конца.
- **`--cfg-scale` обязан быть 1.0.** FLUX.1-schnell дистиллирована под малое
  число шагов и не использует classifier-free guidance. Другое значение
  испортит результат.
- **Увеличивать `--steps` бессмысленно.** `schnell` дистиллирована ровно под
  четыре шага; на восьми она потратит вдвое больше времени с тем же
  результатом. Это отличает её от обычных диффузионных моделей.
- **Устройство Vulkan не навязываем.** В системе два устройства — настоящая
  видеокарта и программный `llvmpipe`, — но ggml сам отбрасывает второе.
  Зашитый `GGML_VK_VISIBLE_DEVICES=0` сломался бы на машине с другим
  порядком перечисления.
- **Размеры кратны 16.** `align16()` в `gpic.py` округляет запрошенное
  разрешение; для 1920x1200 округление не нужно, но для произвольного —
  да.
- **Время определяется вычислениями, а не перекачкой весов.** Прогнать 8 ГБ
  через шину стоит 0.08 с, а шаг занимает 84 — то есть в тысячу раз больше.
  Отсюда два следствия: Q8 идёт не медленнее Q5 (платим только памятью),
  а время растёт как произведение числа параметров на число токенов.
  Не планируй оптимизации исходя из размера весов.
- **Процессор при генерации простаивает** — за 6.5 минут тратит меньше
  минуты. Задействовать 16 потоков для ускорения нельзя: конвейер
  последовательный, гибридный режим ggml нужен для нехватки видеопамяти,
  а не для скорости.
- **Движок выравнивает размеры**, SDXL до кратного 64, FLUX до 16. Поэтому
  `gpic.py` округляет запрос ВВЕРХ и подрезает результат сам через
  `crop_png()`. Разбор PNG написан руками ради обещания «только
  стандартная библиотека»; поддерживается ровно то, что пишет движок —
  8 бит, RGB/RGBA, без чересстрочности. Если движок начнёт писать строки
  с фильтрацией, побайтовые циклы станут медленными — тогда мерить.
- **SDXL-Turbo нельзя просить сразу разрешение экрана.** Он обучен на
  512x512 и на большей площади дублирует объекты: сросшиеся фигуры,
  лишние руки. Поэтому `--fast` рисует в четверть и увеличивает ESRGAN.
  Проверять это надо на портрете, а не на пейзаже: на пейзаже лишний
  горизонт сходит за гряду, и дефект не виден.
- **Негативный промпт у Turbo не работает** — при `cfg-scale 1.0`
  classifier-free guidance выключен. Поднять cfg нельзя, модель под него
  не дистиллирована.
- **Целевое железо — встроенная Radeon 780M**: 4 ГБ выделенной видеопамяти
  плюс ~14 ГБ через GTT. На APU выход за пределы VRAM не штрафуется, как на
  дискретной карте: GTT — та же системная память. Поэтому квантование
  Q5_K_S выбрано по качеству, а не из-за нехватки памяти.
- **ROCm не используется.** Для gfx1103 он официально не поддерживается;
  Vulkan работает без костылей. При неудаче сборки `setup.sh` откатывается
  на режим CPU.
- **Разрешение экрана читается из `/sys/class/drm`, а не через `xrandr`** —
  сессия Wayland, где `xrandr` пуст.
- **Описания придумывает языковая модель, а не списки слов.** Была версия
  с перечислением сюжетов и модификаторов — от неё отказались: сколько ни
  пиши, получается конечный список, который приедается. Сейчас в коде только
  сорок широких тем и пятнадцать творческих углов, конкретику выдумывает
  Qwen2.5-1.5B. Не возвращай перечисление сюжетов.
- **Творческие углы в `CREATIVE_ANGLES` обязательны.** Без заданного
  направления маленькая модель упорно скатывается в «закат над горами» —
  она сильно тяготеет к банальному.
- **Креативность держится на `min-p`, а не на температуре.** Голая высокая
  температура даёт бессвязицу; `min-p` отсекает токены ниже доли от самого
  вероятного и сохраняет связность. Не поднимай температуру без него.
- **Запасной список `FALLBACK_PROMPTS` — не рудимент.** `gpic` обязан
  работать, если `llama.cpp` не собрался или модель не скачана.

## История

Первая версия была на Rust и ходила в удалённый API Pollinations, дорисовывая
результат Lanczos до размера экрана. От неё отказались: анонимный тир
Pollinations заперт на слабой модели с бюджетом 0.59 Мп, а проверенные
альтернативы (Gemini, Together AI) оказались платными. Локальная генерация
сняла вопрос целиком. Код той версии остался в истории git.
