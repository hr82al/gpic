# gpic — генератор обоев для рабочего стола

Дата: 2026-08-28
Статус: утверждён, готов к планированию реализации

## Задача

Нужна консольная утилита, которая одной командой без аргументов кладёт в текущий
каталог свежую красивую картинку под разрешение монитора. Опционально можно
задать свой промпт, своё разрешение и имя файла.

Ограничение, определившее архитектуру: требуется бесплатная удалённая нейросеть
без регистрации и без оплаты.

## Разведка (проверено, не предположения)

Проверялся `image.pollinations.ai` — работает анонимно, без ключа и регистрации.

- `GET https://image.pollinations.ai/prompt/{urlencoded}?width=W&height=H&seed=N&nologo=true` → JPEG, HTTP 200.
- Модель одна: `/models` отдаёт `["sana"]`. Параметр `model=flux` и `model=turbo`
  молча подменяются на неё, `model=kontext` → HTTP 500. Параметр `model` не используем.
- **Соотношение сторон соблюдается, абсолютный размер — нет.** Сервер масштабирует
  под фиксированный пиксельный бюджет:
  - запрос 3840×2160 → отдано 1024×576 (589 824 px)
  - запрос 1024×1024 → отдано 768×768 (589 824 px)
  - запрос 1200×1600 → отдано 665×886 (589 390 px)

  Бюджет постоянен ≈ 0.59 Мп. Следствие: клиенту **не нужна** своя математика
  «вписать в потолок» — запрашиваем целевые W×H, получаем правильную пропорцию.
- Первая генерация ≈ 35 с. Повтор с тем же seed отдаётся из кеша мгновенно
  (проверено: тот же seed → байт в байт тот же размер ответа).
- Сервис иногда залипает: один запрос не ответил за 2 минуты. Это штатное
  поведение, к которому нужно готовиться, а не аномалия.

Экран целевой машины: 1920×1200, выход HDMI-A-1, сессия Wayland (`xrandr` пуст,
`/sys/class/drm/card0-HDMI-A-1/modes` содержит `1920x1200` первой строкой).

## Решения и их обоснование

**Апскейл вместо нативного размера.** 0.59 Мп против 2.3 Мп экрана — увеличение
≈1.9×. Детализация интерполированная, не «настоящая»; на дистанции просмотра обоев
это приемлемо. Утверждено пользователем осознанно. 4K из требований исключён.

**Один провайдер, без trait-абстракции.** Абстракция ради единственного рабочего
бэкенда — лишняя. Если Pollinations перестанет работать, добавить второй бэкенд
по факту дешевле, чем поддерживать обобщение сейчас.

**Чистый Rust, без внешних бинарников.** Апскейл через крейт `image`, не через
`convert`/`ffmpeg`: их наличие на машине пользователя не гарантировано.

**Без эмуляции браузера.** Рассматривалась как запасной путь; не нужна, поскольку
HTTP API доступен анонимно. Headless-хромиум в зависимостях ничем не оправдан.

**Случайный seed обязателен.** Одинаковый seed возвращает закешированную картинку.
Без явной рандомизации «случайная картинка» перестанет быть случайной.

## Интерфейс

```
gpic [ОПЦИИ] [ФАЙЛ]

  -p, --prompt <ТЕКСТ>     промпт; без него — случайный комбинаторный
  -r, --resolution <ШxВ>   напр. 2560x1440; без него — разрешение экрана
  -s, --seed <ЧИСЛО>       воспроизвести конкретную картинку
  ФАЙЛ                     путь или голое имя (тогда — в текущий каталог)
```

Без `ФАЙЛ` имя генерируется как `gpic-ГГГГММДД-ЧЧММСС.jpg` в текущем каталоге.
Формат кодирования выбирается по расширению (`.jpg`/`.jpeg`/`.png`); при
отсутствии или незнакомом расширении — JPEG.

Использованный seed печатается в stdout, чтобы картинку можно было повторить.

## Архитектура

Шесть модулей, каждый с одной ответственностью и тестируемый отдельно.

| Модуль | Ответственность | Зависит от |
|---|---|---|
| `cli` | разбор аргументов, парсинг `ШxВ` | clap |
| `screen` | разрешение экрана из `/sys/class/drm` | — |
| `prompt` | комбинаторная генерация промпта | rand |
| `provider` | HTTP-запрос к Pollinations, таймаут, повтор | reqwest |
| `resize` | Lanczos3 до точных целевых размеров | image |
| `output` | выбор имени файла, кодирование, запись | image |

`main` только связывает их и переводит ошибки в сообщения пользователю.

### Поток

1. `cli` разбирает аргументы.
2. Разрешение: из `-r`, иначе `screen::detect()`.
3. Промпт: из `-p`, иначе `prompt::random()`.
4. Seed: из `-s`, иначе случайный `u32`.
5. `provider::fetch(prompt, w, h, seed)` → байты JPEG (≈0.59 Мп, нужная пропорция).
6. `resize::to(image, w, h)` → точные целевые размеры.
7. `output::save(image, path)`.

### `screen::detect()`

Читает `/sys/class/drm/*/modes`, берёт первый выход, у которого соседний файл
`status` содержит `connected`, и первую строку его `modes` (это предпочитаемый
режим). Парсит `ШxВ`. Работает на Wayland, где `xrandr` бесполезен, и не тянет
зависимостей. Если ничего не найдено — фолбэк 1920×1200 без ошибки.

### `prompt::random()`

Фраза собирается из нескольких коротких зашитых списков — сюжет, свет/время суток,
стиль — по одному случайному элементу из каждого. Даёт сотни комбинаций из
компактного кода. Функция принимает `&mut impl Rng`, чтобы быть детерминированной
в тестах.

### `provider::fetch()`

Промпт кодируется для пути URL. Таймаут запроса 120 с. При таймауте или сетевой
ошибке — один повтор с новым seed (новый seed обходит возможный залипший кеш),
затем осмысленная ошибка. Статус не-200 — ошибка с кодом и телом ответа.

Прокси отдельного кода не требует: `reqwest` по умолчанию читает `HTTP_PROXY` и
`HTTPS_PROXY` из окружения.

Поскольку первая генерация занимает около 35 секунд, перед запросом печатается
строка о том, что идёт генерация — иначе выглядит как зависание.

## Обработка ошибок

Все ошибки поднимаются до `main` через `anyhow` и печатаются в stderr одной
внятной строкой, код возврата 1. Отдельно осмысленные сообщения для: недоступной
сети, таймаута после повтора, не-200 от сервиса, невозможности записать файл
(нет прав, нет каталога), неразбираемого значения `-r`.

## Тестирование

Юнит-тесты без сети:

- парсинг `ШxВ`: корректные значения, мусор, нули, отрицательные, пропущенный `x`;
- `screen`: парсинг фикстуры содержимого `modes`, выбор `connected`-выхода, фолбэк;
- `prompt`: на RNG с фиксированным зерном результат воспроизводим и непустой;
- `output`: голое имя → текущий каталог, путь → как есть, пусто → штамп времени;
  выбор кодировщика по расширению;
- `resize`: результат имеет ровно запрошенные размеры при увеличении, уменьшении
  и совпадающем размере.

Один сетевой интеграционный тест помечен `#[ignore]` — реальный запрос к сервису,
запускается вручную.

Ручная проверка: `cargo run` без аргументов кладёт в текущий каталог JPEG
1920×1200; `cargo run -- -r 800x600 -p "ночной город" out.png` даёт PNG 800×600;
повтор с напечатанным seed даёт ту же картинку.

## Зависимости

`clap` (derive), `reqwest` 0.13 (`blocking`, `rustls`, `system-proxy`), `image`, `rand`,
`chrono` (метка времени в имени файла), `anyhow`. Dev-зависимость: `tempfile`.

В reqwest 0.13 фича TLS называется `rustls`, а не `rustls-tls`, и чтение
`HTTP_PROXY`/`HTTPS_PROXY` требует отдельной фичи `system-proxy` — проверено.

## Вне области

Установка обоев в систему, пакетная генерация, история/галерея, конфиг-файл,
несколько провайдеров, апскейл нейросетью.
